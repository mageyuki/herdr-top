# Stable Task History and Active-Time Rates

## Status

Approved for implementation on 2026-08-27.

## Context

Herdr Top currently has three related truthfulness defects.

1. Herdr 0.8.2 emits the external event name
   `pane.agent_status_changed`, while one collector parser accepts only the
   legacy underscore spelling. A snapshot can therefore say `idle` after the
   pane has returned to `working`.
2. A Task Run's output-token rate divides all observed output tokens by wall
   time since the first telemetry sample. Idle time continuously lowers the
   displayed rate even though no generation work is taking place.
3. Provider backfill publishes intermediate historical lifecycle facts. An
   old native session can temporarily appear as `working` and then disappear
   when its later terminal record is parsed.

Session history also needs an explicit UI contract. A Task Run is one native
session, not one Pane. Exiting an agent and starting a new native session in
the same Pane must append another root. Resuming the same native session must
reuse its existing root.

## Goals

1. Converge live pane status from both the installed dotted Herdr event and
   the legacy underscore spelling.
2. Report output-token rate using only reliably observed `working` time.
3. Never mix pre-measurement tokens or time into a new rate measurement.
4. Keep same-Pane native sessions as stable, append-only root history.
5. Keep root, child, and grandchild terminal Task Runs visible for one hour,
   then hide them from the default tree while retaining DB and Summary data.
6. Prevent historical backfill intermediates from entering the default tree.
7. Preserve Task semantics, native-session lifecycle, execution state, and
   relationship state as separate axes.

## Non-goals

- Reconstruct working time before this version began observing it.
- Count idle, blocked, queued, unknown, or terminal intervals as working.
- Infer successful completion from a generic execution disappearance.
- Change the 30-day Task Run retention policy or the event-ring policy.
- Reverse the existing oldest-first display ordinal.
- Scrape terminal contents.

## Approved user contract

### Identity and ordering

- One native session ID maps to one Task Run root.
- A resume with the same provider and native session ID reuses that row.
- A new native session ID in the same Pane creates a new root row.
- Siblings at every depth are sorted by ascending immutable
  `display_ordinal`: oldest at the top, newest appended below.
- A status change never changes an ordinal or reorders a row.
- Follow mode remains pinned to the newest visible row at the bottom. Manual
  navigation disables follow until the operator re-enables it.

### Session outcomes

The visible operational outcome is:

| Evidence | Effective status |
| --- | --- |
| Normal `SessionEnd` / `/exit` | `done` |
| Explicit abort | `cancelled` |
| Explicit failure | `error` |
| Execution disappears without an outcome | `unknown` |

A normal session end is not a semantic Controller `complete`. It is persisted
as native-session lifecycle evidence so the durable semantic `TaskState`
remains independently inspectable. A later resume clears that lifecycle end
and reopens the same row.

Semantic terminal Task states still outrank every runtime observation. A
persisted native-session end outranks non-terminal semantic states and live
runtime fallback evidence. Detail exposes both the durable state and the
effective status source.

### Visibility

- `done`, `error`, `cancelled`, and terminal-like `unknown` rows remain in the
  default tree for exactly `DEFAULT_TERMINAL_VISIBILITY_MS`, currently one
  hour, at root, child, and grandchild depth.
- After the boundary they are hidden from the default tree but remain in the
  database and Summary until ordinary retention removes them.
- If an individually visible descendant needs an expired ancestor to preserve
  the tree path, the ancestor remains visible as a structural row.
- Operator dismissal remains a separate explicit visibility action.

### Output-token rate

- The denominator is the sum of reliably observed intervals whose run-level
  operational activity is `working`.
- `idle`, `blocked`, `queued`, `unknown`, `done`, `error`, and `cancelled`
  freeze the denominator.
- For a Task Run present in multiple Panes, working activity is an OR: the run
  is working when at least one exact occurrence is working. Time is never
  multiplied by the number of Panes.
- The numerator contains only output tokens observed after a reliable
  measurement baseline. It includes delayed token reports received while the
  status is idle because the tokens were generated by the measured work; idle
  still adds no time.
- Existing tokens and unobserved time at upgrade, cold restore, or observation
  gap are excluded. The UI renders an em dash until at least two trustworthy
  observations bound a positive working interval.
- The per-run rate is measured tokens divided by measured working seconds.
- Summary's mean rate is the aggregate measured-token numerator divided by the
  aggregate measured-working-time denominator. It is not the arithmetic mean
  of per-run rates.
- The existing total-output-token column remains a lifetime total and is not
  relabeled as the measured numerator.

## Architecture

### Shared status projection

Move run-status derivation out of the TUI-only module into a crate-internal
status projection module. It retains the already-reviewed occurrence-specific
precedence and provides two consumers:

1. TUI rows receive `DisplayStatus` for the exact rendered occurrence.
2. The rate tracker receives one run-level `Working` or `Paused` decision.

Run-level working is derived without double counting:

1. Semantic or native-session terminal evidence is paused.
2. `queued` and semantic `blocked` are paused.
3. Any exact Pane occurrence whose authoritative pane status is `working`
   makes the run working.
4. When pane status is absent, a matching non-terminal working execution can
   make it working.
5. A headless run uses only its own newest eligible root Agent Node.
6. `TaskState::Running` remains the final working fallback.

The projection never aggregates descendant Agent activity into a parent.

### Herdr event normalization

`pane_agent_status_observation` accepts exactly these two spellings:

- `pane.agent_status_changed` (installed Herdr 0.8.2 wire form)
- `pane_agent_status_changed` (legacy compatibility)

Both the event classifier and event body dispatcher use the same predicate;
there must not be a second spelling-specific match arm. Snapshot and event
paths continue to update the same transient pane-status map atomically.

### Native-session lifecycle

Add a Controller event kind `session_ended` for hook transport. It is valid
only for a known run with a non-empty provider/native-session binding and does
not create a forward reference. The hook adapter maps `SessionEnd` to this
event instead of `dismiss`.

Task Run state gains optional persisted session-end evidence:

```rust
pub struct NativeSessionEnd {
    pub status: NativeSessionEndStatus,
    pub at_ms: i64,
}

pub struct NativeLifecycleWatermark {
    pub source_at_ms: i64,
    pub observed_at_ms: i64,
    pub source_order: String,
}

pub enum NativeSessionEndStatus {
    Done,
    Error,
    Cancelled,
    Unknown,
}
```

`task_started`, a matching live execution, or a matching provider liveness
fact clears the session end. Semantic terminal Task states are not reopened.
Every end and reopen also advances the persisted watermark. Ordering compares
the trustworthy source timestamp first, then collector observation time, then
a stable source/event identity. The latter two fields are deterministic
tie-breakers only; an older source fact can never re-close a newer start after
delayed delivery or restart. `session_ended` is idempotent for the same
watermark/status and ignores a stale or unknown/unbound observation as a
diagnostic no-op. A normal hook end writes `Done` using the hook emission time;
provider facts use their trustworthy source timestamp.

Provider lifecycle mapping is explicit:

| Evidence | Axis and result |
| --- | --- |
| Hook `SessionStart` | native lifecycle reopen |
| Hook `SessionEnd` | native lifecycle `Done` |
| Codex turn complete | runtime idle only; not a session end |
| Codex explicit turn abort | native lifecycle `Cancelled`, resumable |
| Provider root failure with an explicit outcome | native lifecycle `Error` |
| Root lane close/inactivity without an outcome | native lifecycle `Unknown` |
| Subagent/task completion | semantic Task completion as today |

`LaneClose` must not irreversibly write `TaskState::EndedUnknown` for a native
root. Child Task semantics remain authoritative and separate.

### Historical drain protocol

Provider discovery remains bounded and incremental; it must not retain every
historical run key in memory. Each startup/backfill pass creates one stable
`HistoryDrainId` from the provider plus a streaming digest of its sorted frozen
artifact manifest. The manifest records each stable artifact identity,
generation, and frozen goalpost in SQLite. Historical run association is also
spilled to SQLite as events are reduced; the provider `Synthesis` object never
owns a drain-wide run-key set.

The protocol is:

1. Provider events before their manifest goalposts carry
   `ObservationOrigin::Historical { drain_id, artifact_id }`. The event's
   Task Run mutation and idempotent `history_drain_runs` association persist in
   the same transaction.
2. A Task Run first created solely by historical observations is persisted
   with `history_ready = false` and its latest trustworthy provider timestamp.
   Live Controller, execution, or post-goalpost provider evidence immediately
   makes the run ready and is never hidden by later enrichment. Historical
   enrichment may add lifetime metadata to an already-live run, but may not
   regress a newer live status or lifecycle watermark.
3. Parsing advances an artifact byte cursor only after its event was accepted
   into the bounded pending buffer. When the buffer is full, the provider stops
   and resumes from the same position; it never drops a distinct historical
   transition. The worker processes no new input while prior pending output
   cannot drain.
4. After every artifact reaches its frozen goalpost, `PendingEvents` enqueues
   one barrier behind all ordinary lane and coalesced-entity slots. The barrier
   is not eligible for egress until those slots are empty. Once emitted, the
   provider holds exactly that one barrier and performs no further parsing
   until it receives a finalization acknowledgement.
5. The collector stages finalization without publishing it. One SQLite
   transaction marks the drain complete, makes its still-historical runs ready,
   and closes ready non-live/nonterminal runs as native lifecycle `Unknown` at
   their latest trustworthy provider timestamp. Only `Durable` or known
   `CommittedButDegraded` permits the reducer to apply the matching in-memory
   page updates and publish once.
6. `NotCommitted`, `Skipped`, and unresolved `DurabilityUnknown` keep every
   affected row suppressed. The same barrier is retried after writer recovery;
   a durability-unknown result is resolved by querying the drain-completion row
   before retry. This is bounded to one provider barrier and does not depend on
   a health probe replaying a lost batch.
7. A crash before finalization leaves durable `history_ready = false` rows
   suppressed. A replayed drain is idempotent. A newer completed manifest may
   supersede an incomplete manifest only when its artifact identities and
   generations prove that every old goalpost is covered; otherwise the old
   rows remain suppressed rather than being guessed ready.

This permits ordinary reducer and persistence progress while ensuring the
operator sees only a durable coalesced end state. A historical terminal older
than one hour remains in DB and Summary without flashing in the default tree.

A drain-synthesized `Unknown` writes a lifecycle watermark whose
`source_at_ms` is the run's latest trustworthy provider timestamp,
`observed_at_ms` is the barrier observation time, and `source_order` is the
stable drain/run identity. Finalization compares that complete tuple against
the currently persisted watermark in the same transaction. A live start with
a later source timestamp wins whether it arrives before or after finalization;
an older delayed start does not. Equal source timestamps use observation time
and stable source order exactly as other lifecycle facts do.

### Active-time rate ledger

Persist closed totals separately from the transient observation cursor:

```rust
pub struct RunRateTotals {
    pub output_tokens: u64,
    pub working_ms: i64,
}

pub struct RunRateCursor {
    pub baseline_output_tokens: u64,
    pub last_observed_at_ms: i64,
    pub working: bool,
    pub measurement_epoch: u64,
}
```

`RunRateTotals` is stored in SQLite. `RunRateCursor` is process-local and is
never restored across a cold start. Rate observations carry an explicit
measurement epoch and origin. Historical observations update lifetime
telemetry but only rebaseline; they never accrue. The first live observation
after a durably acknowledged historical barrier establishes the live baseline.
Entering `Disconnected` or `Reconciling`, queue-overflow recovery, cold start,
or an identity-basis change increments the epoch and clears cursors before any
stale sweep can accrue. Reconciliation establishes a new baseline only after
the authoritative snapshot is installed.

On each relevant status, telemetry, topology, provider-lifecycle, and five
second stale-sweep observation, the reducer derives activity, cumulative
telemetry, identity, epoch, and timestamp from one coherent post-transition
snapshot:

1. Clamp time monotonically to the cursor's prior timestamp.
2. If the prior cursor was working, add the elapsed interval to
   `working_ms`.
3. If the cumulative output-token count has increased, add the positive
   delta to measured `output_tokens`, regardless of the new status.
4. If the cumulative count decreased, the observation is historical, the
   epoch changed, or identity merge changed its basis,
   rebaseline without adding a synthetic delta.
5. Store the current cumulative total, timestamp, and run-level working flag
   as the new cursor.

The five-second sweep checkpoints active runs in one persistence batch. A
crash can lose at most the uncheckpointed tail; restart never bridges the
offline gap. Graceful shutdown performs one final checkpoint.

Run merges add the two persisted totals, discard both cursors, and establish a
fresh canonical baseline on the next observation. Positive persisted totals
remain renderable after restart even though the cursor is absent; a missing
cursor prevents accrual, not display. Retention cascades totals with the Task
Run.

## Persistence

Schema v6 adds:

- nullable session-end fields and lifecycle-watermark columns on `task_runs`;
- `history_ready` and latest-provider-timestamp columns on `task_runs`;
- `history_drains`, `history_drain_artifacts`, and `history_drain_runs` tables
  with foreign keys and idempotent uniqueness constraints;
- a `run_rate_totals` table keyed by `run_id`, with non-negative integer
  checks and `ON DELETE CASCADE`.

Migration rules:

- Existing Task Runs migrate as `history_ready = true`.
- Existing rows have no session-end evidence.
- Existing terminal visibility timestamps retain their current semantics.
- Existing runs have no rate row and render `—` until a live baseline and
  positive working interval exist. Restored rows with already-persisted
  positive measured totals render those totals without a cursor.
- The pre-migration SQLite online backup remains mandatory.
- Reader restore reconstructs persisted session/history/rate totals but no
  pane status or rate cursor.

SQLite integer conversion is checked. The measured output-token total and
measured working-millisecond total saturate before enqueue at the persisted
domain maximum `i64::MAX`; saturation records a bounded diagnostic counter. No
`u64` value above SQLite's signed integer domain reaches the writer, wraps
negative, or degrades the transaction.

## TUI and Summary projection

The effective status precedence becomes:

1. semantic terminal `TaskState`;
2. persisted native-session end;
3. semantic `queued` or `blocked`;
4. exact pane status;
5. matching execution;
6. own root Agent Node;
7. running/fallback.

`StatusSource` gains `NativeSessionLifecycle`. Detail includes the session-end
status/time, lifecycle watermark, history readiness, measured output tokens,
measured working time, and whether the current rate cursor is initialized.

Default visibility is computed as a set before rows are emitted. It first
selects individually visible runs, then closes that set over execution-edge
ancestors. A hidden ancestor does not suppress a visible descendant.

Tree and DAG both retain ascending `display_ordinal`. Follow mode selects the
last visible row. The shared visibility set controls only default-tree/DAG
placement and their visible counts. Summary does not consume that set: it
includes every store-retained run, including default-hidden terminal history,
and uses the active-time ledger for its aggregate rate.

## Failure handling

- Unknown external event spellings remain ignored; only the two approved
  spellings are aliases.
- A historical drain never marks a run ready before all admitted records to
  the complete manifest goalpost have left provider pending buffers and the
  finalization transaction is known committed.
- Failed readiness finalization retains one acknowledged barrier and retries
  explicitly. Writer-health probing alone is not treated as batch replay.
- Missing rate totals, zero working time, clock reversal, or counter regression
  render `—`, never NaN or infinity. An absent cursor does not hide positive
  persisted totals.
- Session end for an unknown or unbound run is a diagnostic no-op.

## Verification contract

Implementation is test-first. Required regression coverage includes:

1. Dotted and underscore pane-status events produce identical observations;
   the installed dotted spelling updates idle to working through the complete
   collector path.
2. `SessionEnd` produces `done`, remains visible for one hour, survives
   restore, and a same-session resume reopens the same ordinal.
3. A different native session in the same Pane appends a second root below the
   first.
4. Root, child, and grandchild terminal expiration use the same boundary, and
   an otherwise expired ancestor remains while a descendant is visible.
5. Historical intermediate working facts never enter default-visible rows;
   incomplete drains remain suppressed; completed old history is available to
   Summary. Mixed lane/entity saturation, more than 4,096 distinct historical
   runs, parse failure, shutdown, crash/restart, and every writer durability
   outcome preserve the barrier contract.
6. Working to idle freezes the rate denominator; idle to working resumes it;
   blocked, queued, unknown, and terminal periods remain excluded.
7. Multi-sample historical replay, disconnect/reconcile, queue-overflow
   recovery, upgrade, and restart exclude old tokens and offline time. New
   measurements show `—` until positive measured work; restored positive
   totals remain renderable without a cursor.
8. Delayed token reports after idle still enter the measured numerator.
9. Shared Pane occurrences do not double-count working time.
10. Rate totals, lifecycle ends/watermarks, drain readiness, and associations
    round-trip, merge through `apply_binding_plan_at`, prune, and migrate from
    schema v5 correctly. Merge rules are additive totals with absorbed-row
    removal, maximum provider timestamp, no cursor merge, readiness preserved
    by live evidence or completed drain coverage, and deterministic newest
    lifecycle watermark.
11. Tree, DAG, Detail, filter, Summary, narrow rendering, and follow behavior
    preserve the approved contract.
